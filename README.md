#WordVerse
**Every word opens a universe.**

WordVerse is an open-source, AI-powered vocabulary explorer for people learning English. Add a word and it appears as an orb in a 3D universe, connected to synonyms, opposites, phrases and related ideas. Click any connection to see what it means, how it differs, and an example sentence. Practise recalling your words, and your progress is saved in your browser.

An **open-weight language model** (Qwen3-4B by default, running locally through Ollama) writes entries for new words, extra examples, simpler explanations and relationship explanations. A small **hand-curated lexicon** provides verified data for common words. The interface always shows which is which.


## Who it helps

People learning English as an additional language: international students, newcomers (for example people who recently moved to Toronto), and anyone who wants to understand how words connect. A learner who knows *overwhelmed* can discover *swamped*, *burdened* and *have too much on your plate*, and see how they differ in strength and tone.

## Features

- **3D word universe** (React Three Fiber): pan, zoom, click to select. Saved words are large violet orbs; suggested connections are small cyan orbs. Selecting a word flies the camera to it and highlights its links.
- **Relationships you can tell apart without colour**: synonym `=`, near-synonym `≈`, opposite `↔`, phrase `“”`, related idea `~`. Each also has its own line style, and a legend explains them.
- **Trust labels**: every definition, example and relationship shows **✓ Curated** or **✦ AI-generated**. AI output is validated (JSON shape, relationship types, examples must contain the word) and anything malformed is discarded.
- **Add any word**: curated words load instantly. Other words are generated by the open-weight model. Unknown or misspelled words get a clear message.
- **AI help on demand**: *Another example*, *Explain it more simply*, *Explain how they connect*.
- **Practice**: multiple-choice (with three or more words) or reveal-and-self-check. A simple priority rule shows new and difficult words first. It is not a full spaced-repetition algorithm.
- **Persistence**: saved words and review results survive page refreshes (browser local storage).
- **Accessibility**: full keyboard use (every orb label is a button), visible focus, a non-3D **List view**, `prefers-reduced-motion` support (no auto-rotation or pulsing), text labels alongside colour, ARIA live regions for status and errors. If WebGL is unavailable the app switches to the list automatically.
- **Graceful failure**: if the AI is offline, saved words, curated words and practice all keep working, and the status line says so.

## Open-source AI used

| | |
|---|---|
| **Model** | [Qwen3-4B](https://huggingface.co/Qwen/Qwen3-4B), a small language model (4B parameters, under the 10B threshold) |
| **License / terms** | Apache-2.0 per the model page. Please re-verify on the [model page](https://huggingface.co/Qwen/Qwen3-4B) |
| **How it runs** | Locally through [Ollama](https://ollama.com) (`qwen3:4b`). Any OpenAI-compatible server (vLLM, llama.cpp, LM Studio, an open-model host) also works |
| **What it does** | Generates entries for words outside the curated list, new example sentences, simple explanations, and explanations of how two words relate |

No closed AI API is used. The model is configurable with `AI_MODEL`, so you can swap in another open-weight model (update `THIRD_PARTY_NOTICES.md` if you do).

## Getting started

### Prerequisites

- Node.js 18.18 or newer
- [Ollama](https://ollama.com/download) (or another model server, see below)
- About 3 GB free memory for the 4B model (quantized)

### Run it

```bash
# 1. Get the code
git clone https://github.com/<your-username>/wordverse.git
cd wordverse

# 2. Install dependencies
npm install

# 3. Get the model (one time)
ollama pull qwen3:4b

# 4. Configure
cp .env.example .env.local

# 5. Start (Ollama runs in the background on most installs; otherwise: ollama serve)
npm run dev
```

Open http://localhost:3000. The status line under the title shows whether the model is reachable. Without the model, the app still works with the 34 curated words.

### Other commands

```bash
npm run build      # production build
npm start          # run the production build
npm test           # unit tests
npm run typecheck  # TypeScript
npm run lint       # ESLint
```

## Configuration

Copy `.env.example` to `.env.local`.

| Variable | Default | Meaning |
|---|---|---|
| `AI_PROVIDER` | `ollama` | `ollama` or `openai-compatible` |
| `AI_BASE_URL` | `http://localhost:11434` | Model server URL |
| `AI_MODEL` | `qwen3:4b` | Model name on that server |
| `AI_API_KEY` | *(empty)* | Only if your host needs a key |
| `AI_TIMEOUT_MS` | `60000` | Wait time before a friendly timeout error |

Keys and server URLs stay on the server (Next.js API routes). They are never sent to the browser. Never commit `.env.local`.

## How it works

```
Browser (React, R3F, local storage)
   │  POST /api/word      → curated lexicon first, else the model (validated, labelled)
   │  POST /api/assist    → example / simplify / relation, via the model
   │  GET  /api/health    → is the model reachable?
   ▼
Next.js API routes ──► Ollama or OpenAI-compatible server ──► open-weight model
```

1. **Input check** (`src/lib/normalize.ts`): trims, lowercases, allows letters, spaces, hyphens and apostrophes only, which also keeps odd text out of prompts.
2. **Lookup** (`src/lib/lexicon`): curated entries are returned as verified data.
3. **Generation** (`src/lib/ai`): otherwise the model is asked for a strict JSON entry. `validate.ts` extracts and checks it, normalises relationship types, removes self-links and duplicates, and rejects examples that do not use the word. One retry on bad output.
4. **Graph** (`src/lib/graph.ts`): deterministic layout. Saved words sit on a sphere; each word's connections are placed around it. A connection shared by several saved words becomes one node with several links.
5. **Review** (`src/lib/review.ts`): priority rule plus multiple-choice builder.

## Known limitations

- **No evidence yet that the 3D view improves learning.** Spaced and retrieval practice are well supported by research (Kim & Webb, 2022; Carpenter, Pan & Butler, 2022), but this interface has not been tested with learners. See the evaluation plan below.
- **AI can be wrong.** Generated entries are validated for format, not for truth. They are labelled, and should be checked against a dictionary or teacher.
- **Small curated lexicon** (34 words). Everything else relies on the model.
- **Word senses are not separated.** A word like *bank* gets one entry, not one per meaning.
- **English only.**
- **One browser, one device.** Data lives in local storage; clearing site data deletes it. No accounts or sync.
- **Simple review rule**, not full spaced repetition.
- **Crowded graphs.** With many words the 3D view gets busy; the List view is the fallback.
- **Hardware.** The first AI answer can take several seconds on a laptop CPU.

## Planned evaluation

A small study with about 5 to 8 English learners and 1 to 2 tutors: neutral tasks such as "find a word related to *overwhelmed* and explain the link", then ask whether the visualisation helped. Targets from the product plan (not results): 80% complete the core journey unassisted; 90% of a manually reviewed sample of AI output judged accurate and appropriate.
